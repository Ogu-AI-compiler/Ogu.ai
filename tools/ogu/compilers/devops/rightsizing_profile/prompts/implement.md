# Rightsizing Profile — Implementation Guide

## Purpose

A container without resource requests is scheduled on any available node — Kubernetes has no
information to make a placement decision, causing noisy-neighbor CPU starvation across other
workloads. A container limit greater than the node maximum means the pod can never be scheduled
— it stays in Pending forever with no clear error. Kubernetes rejects at admission time any pod
where requests exceed limits — the pod never starts. An HPA with minReplicas > maxReplicas
enters an error state and stops scaling entirely. This compiler enforces all of these constraints
before emitting an artifact.

## Invariants

| Code  | Gate                    | What It Enforces |
|-------|-------------------------|------------------|
| RS001 | spec-valid              | `rightsizing-spec.json` exists, is valid JSON; `service` and `workloads` (non-empty) are declared |
| RS002 | requests-limits-present | Every container declares `requests.cpu`, `requests.memory`, `limits.cpu`, `limits.memory` |
| RS003 | limits-not-exceed-node  | Container limits must not exceed `nodeLimits` when declared (skipped otherwise) |
| RS004 | requests-lte-limits     | `requests.cpu` ≤ `limits.cpu` and `requests.memory` ≤ `limits.memory` per container |
| RS005 | hpa-bounds-valid        | `minReplicas` ≥ 1 and ≤ `maxReplicas`; `targetCPUUtilizationPercentage` is 1–100 |
| RS006 | no-todos                | `rightsizing-spec.json` contains no `TODO`, `FIXME`, `HACK`, `XXX`, or `PLACEHOLDER` |
| RS007 | contract-rightsizing    | Every workload has `name`; every container has `name` |

## Required Output Files

- `rightsizing-spec.json` — author-maintained resource profile declaration
- `rightsizing-artifact.json` — generated by the compiler on full gate pass

## rightsizing-spec.json Structure

```json
{
  "service": "payments-api",
  "nodeLimits": {
    "cpu": "8",
    "memory": "32Gi"
  },
  "workloads": [
    {
      "name": "payments-api",
      "containers": [
        {
          "name": "app",
          "requests": { "cpu": "250m", "memory": "256Mi" },
          "limits":   { "cpu": "1",    "memory": "512Mi" }
        },
        {
          "name": "sidecar",
          "requests": { "cpu": "50m",  "memory": "64Mi" },
          "limits":   { "cpu": "100m", "memory": "128Mi" }
        }
      ],
      "hpa": {
        "minReplicas": 2,
        "maxReplicas": 10,
        "targetCPUUtilizationPercentage": 70
      }
    }
  ]
}
```

## Field Reference

| Field                              | Required    | Notes |
|------------------------------------|-------------|-------|
| `service`                          | yes (RS001) | Service name for identification |
| `workloads`                        | yes (RS001) | Non-empty array of workload resource profiles |
| `workloads[].name`                 | yes (RS007) | Workload name — must match Kubernetes Deployment/StatefulSet name |
| `workloads[].containers`           | yes (RS002) | Array of container resource profiles |
| `containers[].name`                | yes (RS007) | Container name — must match the container spec in the Kubernetes manifest |
| `containers[].requests.cpu`        | yes (RS002) | CPU request (e.g. `250m`, `0.5`, `2`) |
| `containers[].requests.memory`     | yes (RS002) | Memory request (e.g. `256Mi`, `1Gi`) |
| `containers[].limits.cpu`          | yes (RS002) | CPU limit — must be ≥ requests.cpu |
| `containers[].limits.memory`       | yes (RS002) | Memory limit — must be ≥ requests.memory |
| `nodeLimits.cpu`                   | no          | Declare to enable RS003 node capacity check |
| `nodeLimits.memory`                | no          | Node memory capacity |
| `hpa.minReplicas`                  | no          | Minimum pod count — must be ≥ 1 and ≤ maxReplicas |
| `hpa.maxReplicas`                  | no          | Maximum pod count |
| `hpa.targetCPUUtilizationPercentage` | no        | HPA scale target — 1 to 100 |

## Resource Value Formats

| Format  | Example    | Equivalent |
|---------|------------|------------|
| Millicores | `250m` | 0.25 CPU cores |
| Cores   | `1`, `0.5` | 1 or 0.5 CPU cores |
| Mebibytes | `256Mi` | 256 × 1024² bytes |
| Gibibytes | `2Gi`  | 2 × 1024³ bytes |
| Kibibytes | `512Ki` | 512 × 1024 bytes |

## Error Codes

| Code  | Trigger | Fix |
|-------|---------|-----|
| RS001 | `rightsizing-spec.json` missing | Create with `service` and `workloads: [...]` |
| RS001 | `workloads: []` | Add at least one workload with containers |
| RS001 | Missing `service` field | Add `"service": "my-service-name"` |
| RS002 | Container missing `requests.cpu` | Add `"requests": { "cpu": "250m", "memory": "256Mi" }` |
| RS002 | Container missing `limits.memory` | Add `"limits": { "cpu": "1", "memory": "512Mi" }` |
| RS003 | `limits.cpu: "16"` exceeds `nodeLimits.cpu: "8"` | Reduce limit below node capacity or remove `nodeLimits` if node sizing is flexible |
| RS003 | `limits.memory: "64Gi"` exceeds `nodeLimits.memory: "32Gi"` | Reduce memory limit or use a larger node class |
| RS004 | `requests.cpu: "500m"` > `limits.cpu: "250m"` | Increase limit or decrease request — Kubernetes rejects this pod |
| RS004 | `requests.memory: "512Mi"` > `limits.memory: "256Mi"` | Memory request cannot exceed limit |
| RS005 | `minReplicas: 5` > `maxReplicas: 3` | Swap values — minReplicas must be ≤ maxReplicas |
| RS005 | `minReplicas: 0` | Set to at least `1` — zero allows unexpected scale-to-zero |
| RS005 | `targetCPUUtilizationPercentage: 150` | Must be 1–100 — use `70` for most services |
| RS006 | `"cpu": "TODO"` | Replace with a real value like `"250m"` |
| RS007 | Workload missing `name` | Add `"name": "my-deployment"` |
| RS007 | Container missing `name` | Add `"name": "app"` matching the Kubernetes container name |
