# Kubernetes Ingress / Gateway Compiler — Implementation Guide

## Purpose

Define a Kubernetes Ingress or Gateway API resource that routes external traffic into the
cluster. An Ingress with public hosts but no TLS serves credentials in plaintext — every
request is interceptable. An Ingress with no `ingressClass` is claimed by every controller
in the cluster, producing undefined routing. A TLS entry for a host with no matching rule
serves a certificate but returns 404 for every request. This compiler catches all of these
before emitting an artifact.

## Invariants

| Code  | Gate              | What It Enforces |
|-------|-------------------|------------------|
| KI001 | spec-valid        | `k8s-ingress-spec.json` exists, is valid JSON; `name` and a non-empty `rules` array are required; `kind` must be `Ingress`, `Gateway`, `HTTPRoute`, or `GRPCRoute` |
| KI002 | hostnames-valid   | Every rule must declare a `host`; catch-all (no host) rules are rejected; duplicate hosts across rules produce undefined routing |
| KI003 | path-rules-valid  | Every path entry needs a path, `pathType` (`Prefix`/`Exact`/`ImplementationSpecific`), and backend with service name and port |
| KI004 | tls-consistent    | Every TLS entry must have a `secretName` and `hosts`; every TLS host must have a matching rule. Skipped when `tls` is absent |
| KI005 | backends-resolve  | All backend service names in path rules must be listed in `spec.backends`. Skipped when `backends` is absent |
| KI006 | no-todos          | `k8s-ingress-spec.json` contains no `TODO`, `FIXME`, `HACK`, `XXX`, or `PLACEHOLDER` markers |
| KI007 | contract-k8s-ingress | Public-facing hosts must have TLS; `ingressClass` must be declared to prevent multi-controller conflicts |

## Required Output Files

- `k8s-ingress-spec.json` — Ingress/Gateway declaration (name, rules, TLS, backends)
- `k8s-ingress-artifact.json` — generated by the compiler on full gate pass

## k8s-ingress-spec.json Structure

```json
{
  "name": "api-ingress",
  "kind": "Ingress",
  "namespace": "production",
  "ingressClass": "nginx",
  "rules": [
    {
      "host": "api.example.com",
      "paths": [
        {
          "path": "/",
          "pathType": "Prefix",
          "backend": { "service": "api-service", "port": 80 }
        },
        {
          "path": "/admin",
          "pathType": "Exact",
          "backend": { "service": "admin-service", "port": 8080 }
        }
      ]
    }
  ],
  "tls": [
    { "hosts": ["api.example.com"], "secretName": "api-tls-cert" }
  ],
  "backends": ["api-service", "admin-service"]
}
```

| Field          | Required     | Notes |
|----------------|--------------|-------|
| `name`         | yes          | Used in IR ID: `K8S_INGRESS:{name}` |
| `kind`         | no           | Defaults to `Ingress`; enum: `Ingress`, `Gateway`, `HTTPRoute`, `GRPCRoute` |
| `namespace`    | recommended  | Not required by gate but strongly recommended |
| `ingressClass` | yes (KI007)  | Or set via annotation `kubernetes.io/ingress.class` |
| `rules`        | yes          | Non-empty array; each entry needs `host` and `paths` |
| `tls`          | yes (KI007)  | Required when rules have hosts; each entry needs `secretName` and `hosts` |
| `backends`     | recommended  | When declared, all backend services are validated against this list |

## pathType Reference

| pathType | Behaviour |
|----------|-----------|
| `Prefix` | Matches any path that starts with the declared prefix (`/api` matches `/api/v1`, `/api/v2`) |
| `Exact`  | Matches only the exact path (`/admin` does not match `/admin/`) |
| `ImplementationSpecific` | Matching depends on the ingress controller — avoid unless required |

## Error Codes

| Code  | Trigger | Fix |
|-------|---------|-----|
| KI001 | `k8s-ingress-spec.json` missing | Create the file with `name` and `rules` |
| KI001 | `kind: "VirtualService"` | Use `Ingress`, `Gateway`, `HTTPRoute`, or `GRPCRoute` |
| KI001 | `rules` is empty | Add at least one rule with `host` and `paths` |
| KI002 | Rule with no `host` | Add `host: "api.example.com"` to the rule |
| KI002 | Duplicate `host` values | Each hostname may appear in only one rule |
| KI003 | Path entry missing `backend` | Add `backend: { service: "api-service", port: 80 }` |
| KI003 | `pathType: "Wildcard"` | Use `Prefix`, `Exact`, or `ImplementationSpecific` |
| KI004 | TLS entry missing `secretName` | Add `secretName: "api-tls-cert"` to the TLS entry |
| KI004 | TLS host `"api.example.com"` has no matching rule | Add a rule for `host: "api.example.com"` or remove from TLS |
| KI005 | Backend `"admin-service"` not in `spec.backends` | Add `"admin-service"` to the `backends` array |
| KI007 | Public host with no `tls` | Add `tls: [{ hosts: ["api.example.com"], secretName: "..." }]` |
| KI007 | No `ingressClass` | Add `ingressClass: "nginx"` (or `"traefik"`, `"haproxy"`, etc.) |
