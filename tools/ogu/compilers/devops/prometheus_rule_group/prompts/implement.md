# Prometheus Rule Group — Implementation Guide

## Purpose

A duplicate alert name in Prometheus is not an error — the second definition silently overwrites
the first, and one of your conditions is never evaluated. An alert without a PromQL expression
compiles but never fires. An alert with an unrecognised severity label breaks PagerDuty routing
trees and Grafana filtering. A recording rule name that violates the metric naming convention
is rejected by Prometheus at load time — taking down all rules in that group. This compiler
enforces all of these constraints before emitting an artifact.

## Invariants

| Code  | Gate                        | What It Enforces |
|-------|-----------------------------|------------------|
| PR001 | spec-valid                  | `prometheus-rules-spec.json` exists, is valid JSON; `groups` is a non-empty array |
| PR002 | alert-names-unique          | Every alert name is globally unique across all groups — duplicates silently shadow |
| PR003 | alerts-have-required-fields | Every alert declares `expr`, `labels.severity`, and `annotations.summary` |
| PR004 | recording-rule-names-valid  | Recording rule names match `[a-zA-Z_:][a-zA-Z0-9_:]*` — invalid names fail at load |
| PR005 | severity-labels-valid       | `labels.severity` must be one of: `critical`, `warning`, `info`, `page`, `ticket` |
| PR006 | no-todos                    | `prometheus-rules-spec.json` contains no `TODO`, `FIXME`, `HACK`, `XXX`, or `PLACEHOLDER` |
| PR007 | contract-prometheus-rules   | At least one alert rule unless `recordingOnly: true`; every alert needs `runbook_url` or `runbook` |

## Required Output Files

- `prometheus-rules-spec.json` — author-maintained rule group declaration
- `prometheus-rules-artifact.json` — generated by the compiler on full gate pass

## prometheus-rules-spec.json Structure

```json
{
  "namespace": "payments",
  "groups": [
    {
      "name": "payments.alerts",
      "rules": [
        {
          "alert": "HighErrorRate",
          "expr": "rate(http_requests_total{status=~\"5..\"}[5m]) > 0.05",
          "for": "5m",
          "labels": { "severity": "critical" },
          "annotations": {
            "summary": "HTTP error rate above 5% for 5 minutes",
            "runbook_url": "https://runbooks.internal/payments/high-error-rate"
          }
        }
      ]
    },
    {
      "name": "payments.recordings",
      "rules": [
        {
          "record": "payments:http_errors:rate5m",
          "expr": "rate(http_requests_total{status=~\"5..\"}[5m])"
        }
      ]
    }
  ]
}
```

## Field Reference

| Field                      | Required    | Notes |
|----------------------------|-------------|-------|
| `groups`                   | yes (PR001) | Non-empty array of rule groups |
| `groups[].name`            | yes         | Group name — unique per file |
| `groups[].rules`           | yes         | Array of alert or recording rules |
| `rules[].alert`            | alert only  | Alert name — must be globally unique (PR002) |
| `rules[].expr`             | yes (PR003) | PromQL expression — evaluated continuously |
| `rules[].for`              | no          | Duration before alert fires (e.g. `5m`) |
| `rules[].labels.severity`  | yes (PR003) | Must be a recognised severity value (PR005) |
| `rules[].annotations.summary`    | yes (PR003) | Human-readable description |
| `rules[].annotations.runbook_url`| yes (PR007) | Link to resolution runbook |
| `rules[].record`           | recording   | Metric name — must match naming pattern (PR004) |
| `recordingOnly`            | no          | `true` to exempt the spec from the alert-required check |

## Severity Reference

| Value      | Use Case |
|------------|----------|
| `critical` | Service is down or data is being lost — page immediately |
| `warning`  | Degraded but not broken — ticket or on-call notification |
| `info`     | Informational signal — no action required |
| `page`     | Explicit PagerDuty page — bypasses routing rules |
| `ticket`   | Create a JIRA/GitHub issue — next business day |

## Recording Rule Naming

Recording rules must use the Prometheus convention:
`namespace:metric_name:aggregation_operation`

| Valid                          | Invalid              | Reason |
|-------------------------------|----------------------|--------|
| `job:http_requests:rate5m`    | `httpRequestsRate5m` | No colons — won't be rejected but breaks federation conventions |
| `payments:error_rate:avg`     | `error-rate`         | Hyphen not allowed in metric names |
| `slo:availability:ratio`      | `1_bad_name`         | Must start with letter or underscore |

## Error Codes

| Code  | Trigger | Fix |
|-------|---------|-----|
| PR001 | `prometheus-rules-spec.json` missing | Create the file with `groups: [{ name, rules: [...] }]` |
| PR001 | `groups: []` | Add at least one rule group with at least one rule |
| PR002 | Two alerts named `"HighErrorRate"` in different groups | Rename one: `"HighErrorRateGET"` and `"HighErrorRatePOST"` |
| PR003 | Alert missing `expr` | Add `"expr": "rate(http_errors_total[5m]) > 0.1"` |
| PR003 | Alert missing `labels.severity` | Add `"labels": { "severity": "critical" }` |
| PR003 | Alert missing `annotations.summary` | Add `"annotations": { "summary": "Error rate above threshold" }` |
| PR004 | `record: "http-errors-rate"` | Use `"record": "job:http_errors:rate5m"` — hyphens not allowed |
| PR004 | `record: "1_bad_metric"` | Must start with a letter, underscore, or colon |
| PR005 | `labels.severity: "high"` | Use `"critical"` or `"warning"` — `"high"` is not in the allowed enum |
| PR005 | `labels.severity: "urgent"` | Use `"page"` for immediate paging |
| PR006 | `"expr": "TODO: fill in PromQL"` | Write a real PromQL expression — placeholder values never fire |
| PR007 | No alert rules in spec | Add at least one alert rule, or set `"recordingOnly": true` |
| PR007 | Alert missing `runbook_url` | Add `"annotations": { "runbook_url": "https://runbooks.internal/..." }` |
