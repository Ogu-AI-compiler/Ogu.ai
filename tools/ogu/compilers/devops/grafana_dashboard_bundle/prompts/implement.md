# Grafana Dashboard Bundle — Implementation Guide

## Purpose

Grafana silently skips dashboards with JSON parse errors during provisioning — the dashboard
simply does not appear, with no error logged. A datasource UID referenced in a panel but not
declared in the spec causes that panel to fail with "datasource not found" while the rest of
the dashboard loads normally, creating invisible monitoring gaps. Duplicate panel IDs cause
Grafana to render one panel in multiple grid positions — showing the same chart twice while
other panels disappear entirely. This compiler enforces structural correctness before any
dashboard reaches a Grafana instance.

## Invariants

| Code  | Gate                       | What It Enforces |
|-------|----------------------------|------------------|
| GD001 | spec-valid                 | `grafana-dashboard-spec.json` exists, is valid JSON; `dashboards` is a non-empty array |
| GD002 | dashboard-json-valid       | Every `file` referenced in `dashboards` exists on disk and is valid JSON |
| GD003 | required-fields-present    | Every dashboard JSON declares `title`, `panels` (array), and `schemaVersion` |
| GD004 | datasource-uids-declared   | All datasource UIDs in panel fields are declared in `spec.datasources` (skipped if no datasources) |
| GD005 | panel-ids-unique           | No two panels within the same dashboard share the same `id` value |
| GD006 | no-todos                   | `grafana-dashboard-spec.json` contains no `TODO`, `FIXME`, `HACK`, `XXX`, or `PLACEHOLDER` |
| GD007 | contract-grafana-dashboard | Datasources have `uid` and `type`; each dashboard JSON has `uid`; each dashboard has `tags` |

## Required Output Files

- `grafana-dashboard-spec.json` — author-maintained bundle declaration
- `grafana-dashboard-artifact.json` — generated by the compiler on full gate pass
- One or more `*.json` dashboard files referenced by the spec

## grafana-dashboard-spec.json Structure

```json
{
  "namespace": "production",
  "dashboards": [
    { "file": "overview.json" },
    { "file": "latency.json" }
  ],
  "datasources": [
    { "uid": "prometheus-ds",  "type": "prometheus",  "name": "Prometheus" },
    { "uid": "loki-ds",        "type": "loki",         "name": "Loki" }
  ]
}
```

## Dashboard JSON Structure (per dashboard file)

```json
{
  "uid": "overview-dash-001",
  "title": "Service Overview",
  "schemaVersion": 36,
  "tags": ["payments", "sre"],
  "panels": [
    {
      "id": 1,
      "type": "timeseries",
      "title": "Request Rate",
      "datasource": { "uid": "prometheus-ds", "type": "prometheus" }
    },
    {
      "id": 2,
      "type": "stat",
      "title": "Error Rate",
      "datasource": { "uid": "prometheus-ds", "type": "prometheus" }
    }
  ]
}
```

## Field Reference — grafana-dashboard-spec.json

| Field                   | Required    | Notes |
|-------------------------|-------------|-------|
| `dashboards`            | yes (GD001) | Non-empty array of dashboard entries |
| `dashboards[].file`     | yes (GD002) | Path to dashboard JSON file, relative to spec dir |
| `datasources`           | no          | Declare datasources to enable UID validation (GD004) |
| `datasources[].uid`     | yes (GD007) | Unique identifier for the datasource in Grafana |
| `datasources[].type`    | yes (GD007) | Grafana datasource type (prometheus, loki, etc.) |
| `datasources[].name`    | no          | Human-readable name |

## Field Reference — dashboard JSON

| Field           | Required    | Notes |
|-----------------|-------------|-------|
| `uid`           | yes (GD007) | Unique identifier — must be consistent across provisioning |
| `title`         | yes (GD003) | Display name in Grafana catalog |
| `schemaVersion` | yes (GD003) | Grafana schema version — use `36` or later |
| `tags`          | yes (GD007) | Non-empty array for catalog discoverability |
| `panels`        | yes (GD003) | Array of panel objects |
| `panels[].id`   | yes (GD005) | Integer — must be unique within the dashboard |

## Datasource Type Reference

| Type          | Notes |
|---------------|-------|
| `prometheus`  | Metrics — most common |
| `loki`        | Logs |
| `tempo`       | Traces |
| `elasticsearch` | Logs + search |
| `postgres`    | SQL queries |
| `cloudwatch`  | AWS metrics |

## Exempt UIDs (GD004)

These UIDs are never flagged even if not in `spec.datasources`:
- `-- Grafana --` (built-in Grafana datasource)
- Any UID starting with `${` (template variable — resolved at render time)

## Error Codes

| Code  | Trigger | Fix |
|-------|---------|-----|
| GD001 | `grafana-dashboard-spec.json` missing | Create the file with `dashboards: [{ file: "..." }]` |
| GD001 | `dashboards: []` | Add at least one dashboard entry |
| GD002 | `file: "overview.json"` but file does not exist | Create the JSON file at the declared path |
| GD002 | Dashboard file contains malformed JSON | Fix the JSON syntax error (check brackets, commas, quotes) |
| GD002 | Dashboard entry missing `file` field | Add `"file": "dashboard-name.json"` to the entry |
| GD003 | Dashboard missing `title` | Add `"title": "Service Overview"` to the dashboard JSON |
| GD003 | Dashboard missing `panels` or `panels` is not an array | Add `"panels": [...]` |
| GD003 | Dashboard missing `schemaVersion` | Add `"schemaVersion": 36` |
| GD004 | Panel uses `uid: "custom-ds"` not in `spec.datasources` | Add `{ "uid": "custom-ds", "type": "prometheus" }` to `datasources` |
| GD005 | Two panels both have `"id": 1` | Assign unique integer IDs to every panel |
| GD006 | `"uid": "TODO"` in spec | Replace with real datasource UID from Grafana |
| GD007 | Datasource missing `type` | Add `"type": "prometheus"` (or loki, tempo, etc.) |
| GD007 | Dashboard JSON has no `uid` field | Add `"uid": "my-dashboard-001"` — must be stable across deploys |
| GD007 | Dashboard JSON has no `tags` | Add `"tags": ["service-name", "team-name"]` |
