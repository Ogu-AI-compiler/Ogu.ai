# Scheduled Job — Implementation Guide

## Purpose

Define a Kubernetes CronJob that runs reliably without piling up concurrent instances or failing at
admission. A CronJob with no `concurrencyPolicy` defaults to `Allow` — if the job takes longer than
its schedule interval, a second instance starts before the first finishes. Two instances processing
the same database records causes data duplication or deadlocks. An invalid cron expression is
rejected by the CronJob controller at `kubectl apply` time with a cryptic admission error. A secret
env ref without a `secretName` causes the pod to fail to schedule before running a single line of
code. This compiler enforces all of these constraints before emitting an artifact.

## Invariants

| Code  | Gate                  | What It Enforces |
|-------|-----------------------|------------------|
| SJ001 | spec-valid            | `scheduled-job-spec.json` exists, is valid JSON; `name`, `schedule`, `command`, and `image` are declared |
| SJ002 | cron-expression-valid | `schedule` is a valid 5-field cron expression (each field in range) or a recognised shorthand |
| SJ003 | job-template-valid    | Both `command` and `image` are declared — a job without an image cannot schedule; without a command it runs the container's default entrypoint |
| SJ004 | concurrency-policy-set| `concurrencyPolicy` is declared and is one of `Allow`/`Forbid`/`Replace` — absence defaults to `Allow` which causes job pile-up |
| SJ005 | limits-valid          | `backoffLimit`, `successfulJobsHistoryLimit`, `failedJobsHistoryLimit` must be non-negative integers when declared |
| SJ006 | no-undeclared-secrets | Every `envRefs` entry with `secret: true` must declare `secretName` — missing secretName causes pod scheduling failure |
| SJ007 | no-todos              | `scheduled-job-spec.json` contains no `TODO`, `FIXME`, `HACK`, `XXX`, or `PLACEHOLDER` markers |
| SJ008 | contract-scheduled-job| `owner` is declared (for on-call routing); `concurrencyPolicy` is declared |

## Required Output Files

- `scheduled-job-spec.json` — author-maintained job declaration
- `scheduled-job-artifact.json` — generated by the compiler on full gate pass

## scheduled-job-spec.json Structure

```json
{
  "name": "nightly-report",
  "schedule": "0 2 * * *",
  "image": "registry.example.com/reporter:2.1.4",
  "command": ["node", "report.mjs", "--output", "s3://reports/nightly"],
  "owner": "data-team",
  "concurrencyPolicy": "Forbid",
  "backoffLimit": 3,
  "successfulJobsHistoryLimit": 3,
  "failedJobsHistoryLimit": 5,
  "resources": {
    "requests": { "cpu": "100m",  "memory": "128Mi" },
    "limits":   { "cpu": "500m",  "memory": "512Mi" }
  },
  "envRefs": [
    {
      "name": "DB_URL",
      "secret": true,
      "secretName": "nightly-report-secrets",
      "key": "database-url"
    },
    {
      "name": "OUTPUT_BUCKET",
      "value": "s3://reports/nightly"
    }
  ]
}
```

## Field Reference

| Field                        | Required    | Notes |
|------------------------------|-------------|-------|
| `name`                       | yes (SJ001) | CronJob name |
| `schedule`                   | yes (SJ001) | 5-field cron or shorthand |
| `image`                      | yes (SJ001) | Container image — pin to a version tag or SHA |
| `command`                    | yes (SJ001) | Array of strings: the job entrypoint + arguments |
| `owner`                      | yes (SJ008) | Team or email for on-call routing |
| `concurrencyPolicy`          | yes (SJ004) | `Forbid`, `Replace`, or `Allow` |
| `backoffLimit`               | no (SJ005)  | Non-negative integer — retry count |
| `successfulJobsHistoryLimit` | no (SJ005)  | Non-negative integer |
| `failedJobsHistoryLimit`     | no (SJ005)  | Non-negative integer |
| `envRefs[].secretName`       | conditional | Required when `secret: true` |

## Cron Expression Reference

| Field         | Range  | Notes |
|---------------|--------|-------|
| minute        | 0–59   | Supports `*`, `/N`, `a-b`, `a,b` |
| hour          | 0–23   | |
| day-of-month  | 1–31   | |
| month         | 1–12   | |
| day-of-week   | 0–7    | Both 0 and 7 = Sunday |

**Shorthands**: `@yearly`, `@annually`, `@monthly`, `@weekly`, `@daily`, `@midnight`, `@hourly`, `@reboot`

## Concurrency Policy Reference

| Policy  | Behaviour | Use When |
|---------|-----------|----------|
| `Forbid`  | Skip new run if previous is still running | Most jobs — prevents data duplication |
| `Replace` | Cancel current run, start new one | Jobs where freshness matters more than completion |
| `Allow`   | Run in parallel — multiple instances simultaneously | Only for truly idempotent, stateless jobs |

## Error Codes

| Code  | Trigger | Fix |
|-------|---------|-----|
| SJ001 | `scheduled-job-spec.json` missing | Create the file with `name`, `schedule`, `command`, `image` |
| SJ001 | Missing `command` | Add `command: ["node", "job.mjs"]` |
| SJ002 | `schedule: "0 2 * * * *"` (6 fields) | Cron needs exactly 5 fields: `"0 2 * * *"` |
| SJ002 | `schedule: "0 25 * * *"` | Hour field 25 is out of range 0–23 |
| SJ002 | `schedule: "@nightly"` | Not a recognised shorthand — use `@daily` or `@midnight` |
| SJ003 | No `image` | Add `image: "registry.example.com/my-job:1.0.0"` |
| SJ004 | No `concurrencyPolicy` | Add `concurrencyPolicy: "Forbid"` for most jobs |
| SJ004 | `concurrencyPolicy: "forbid"` (lowercase) | Use `"Forbid"` — Kubernetes is case-sensitive |
| SJ005 | `backoffLimit: -1` | Must be a non-negative integer — use `0` for no retries |
| SJ005 | `backoffLimit: 1.5` | Must be an integer, not a float |
| SJ006 | `envRefs: [{ name: "DB_URL", secret: true }]` without `secretName` | Add `secretName: "my-k8s-secret"` |
| SJ008 | No `owner` | Add `owner: "platform-team"` or `owner: "alerts@example.com"` |
