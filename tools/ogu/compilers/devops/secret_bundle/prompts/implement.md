# Secret Bundle — Implementation Guide

## Purpose

Define a complete secret bundle that is auditable, rotation-enforced, and never exposes credential
values in source control. A Kubernetes Secret with `stringData` is only base64-encoded — anyone with
`kubectl get secret` can decode it in one command. A secret with no rotation policy accumulates as a
compliance liability: stale credentials that no one notices until a breach. A secret whose `envKey`
is not declared in the env schema injects values into env vars the service doesn't know about,
causing silent startup errors. A secret path formatted incorrectly for its source fails at runtime
with an opaque lookup error. This compiler enforces all of these constraints before emitting an
artifact.

## Invariants

| Code  | Gate                  | What It Enforces |
|-------|-----------------------|------------------|
| SB001 | spec-valid            | `secret-bundle-spec.json` exists, is valid JSON; `namespace`, `environments`, and `secrets` are declared; each secret has `name`, `envKey`, and a recognised `source` |
| SB002 | keys-mapped-to-env    | Every secret's `envKey` is declared in `env-schema-artifact.json` and marked `secret: true`; gracefully skipped when no artifact exists |
| SB003 | namespace-unique      | No two secrets share the same `name` within the same `namespace`+`environment` combination — duplicates cause non-deterministic resolution |
| SB004 | no-plaintext-values   | YAML files must not contain Kubernetes Secrets with literal `stringData` values — use SealedSecrets or ExternalSecrets |
| SB005 | secret-paths-valid    | Each secret's `path` must conform to the format expected by its `source` — an invalid path causes a runtime lookup failure |
| SB006 | no-todos              | `secret-bundle-spec.json` contains no `TODO`, `FIXME`, `HACK`, `XXX`, or `PLACEHOLDER` markers |
| SB007 | contract-secret-bundle| `rotationPolicy` must be declared and valid; `environments` must be non-empty; secret names must be unique within the bundle |

## Required Output Files

- `secret-bundle-spec.json` — author-maintained bundle declaration
- `secret-bundle-artifact.json` — generated by the compiler on full gate pass

## secret-bundle-spec.json Structure

```json
{
  "namespace": "api-gateway",
  "environments": ["staging", "production"],
  "rotationPolicy": "90d",
  "secrets": [
    {
      "name": "database-password",
      "envKey": "DATABASE_URL",
      "source": "aws-secrets-manager",
      "path": "api-gateway/database-url"
    },
    {
      "name": "stripe-secret-key",
      "envKey": "STRIPE_SECRET_KEY",
      "source": "vault",
      "path": "secret/data/payments/stripe-key"
    },
    {
      "name": "redis-auth-token",
      "envKey": "REDIS_AUTH_TOKEN",
      "source": "gcp-secret-manager",
      "path": "projects/my-project/secrets/redis-auth/versions/latest"
    }
  ]
}
```

## Field Reference

| Field                | Required    | Notes |
|----------------------|-------------|-------|
| `namespace`          | yes (SB001) | Kubernetes namespace — scopes all secrets; avoid `default` |
| `environments`       | yes (SB001) | Non-empty array of deployment targets |
| `rotationPolicy`     | yes (SB007) | See rotation policy reference below |
| `secrets`            | yes (SB001) | Non-empty array of secret entries |
| `secrets[].name`     | yes (SB001) | Unique within namespace+environment |
| `secrets[].envKey`   | yes (SB001) | Runtime env var name — must exist in env schema with `secret: true` |
| `secrets[].source`   | yes (SB001) | See source reference below |
| `secrets[].path`     | conditional | Required for all sources except `sealed-secret` |

## Source Reference

| Source                | Path Format | Example |
|-----------------------|-------------|---------|
| `aws-secrets-manager` | Short name or full ARN | `api-gateway/db-password` |
| `gcp-secret-manager`  | `projects/{project}/secrets/{name}/versions/{version}` | `projects/my-proj/secrets/db-pass/versions/latest` |
| `azure-key-vault`     | `https://{vault}.vault.azure.net/secrets/{name}` | `https://my-vault.vault.azure.net/secrets/db-pass` |
| `vault`               | Alphanumeric slash path | `secret/data/api-gateway/db` |
| `k8s-secret`          | `namespace/secret-name` | `api-gateway/db-credentials` |
| `sealed-secret`       | No path required | Controller manages references |

## Rotation Policy Reference

| Policy  | Meaning |
|---------|---------|
| `30d`   | Rotate every 30 days — appropriate for high-value secrets (DB passwords, API keys) |
| `90d`   | Rotate every 90 days — standard for most production secrets |
| `180d`  | Rotate every 180 days — for low-churn infrastructure secrets |
| `1y`    | Annual rotation — for rarely used or legacy secrets |
| `manual`| Rotate only on explicit operator request — document why |
| `never` | Never rotated — must be explicitly justified and audited |

## Error Codes

| Code  | Trigger | Fix |
|-------|---------|-----|
| SB001 | `secret-bundle-spec.json` missing | Create the file with `namespace`, `environments`, `secrets` |
| SB001 | Secret with `source: "hashicorp-vault"` | Use `"vault"` — not `"hashicorp-vault"` |
| SB001 | Secret missing `envKey` | Add `envKey: "MY_ENV_VAR"` to the secret entry |
| SB002 | `envKey: "DB_URL"` not in env schema | Add `DB_URL` to `env-schema-spec.json` with `secret: true` |
| SB002 | `envKey: "API_KEY"` exists but `secret: false` | Update env schema to set `secret: true` for this key |
| SB003 | Two secrets both named `db-password` in `production` | Rename one or merge them |
| SB004 | `stringData: { password: "my-actual-password" }` in `secret.yaml` | Replace with a SealedSecret or ExternalSecret resource |
| SB005 | GCP path `my-project/my-secret` | Use full path: `projects/my-project/secrets/my-secret/versions/latest` |
| SB005 | Azure path missing `https://` | Use `https://my-vault.vault.azure.net/secrets/my-secret` |
| SB007 | No `rotationPolicy` | Add `rotationPolicy: "90d"` (or another valid policy) |
| SB007 | `rotationPolicy: "60d"` | Not a recognised policy — use `30d`, `90d`, `180d`, `1y`, `manual`, or `never` |
| SB007 | `environments: []` | Add at least one environment: `["staging", "production"]` |
