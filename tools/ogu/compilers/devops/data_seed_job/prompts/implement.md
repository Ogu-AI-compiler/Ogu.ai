# Data Seed Job — Implementation Guide

## Purpose

Define a data seed job that can be re-run safely on any failure without corrupting the database.
A seed job without an idempotency strategy creates duplicate records on re-run, violates unique
constraints, or leaves the database in an inconsistent state. A seed job that targets `production`
without an explicit override can corrupt live user data and violate GDPR compliance. A DB ref without
an `envKey` or `secretName` mapping fails to connect at startup — the job never runs. This compiler
enforces all of these constraints before emitting an artifact.

## Invariants

| Code  | Gate                  | What It Enforces |
|-------|-----------------------|------------------|
| DS001 | spec-valid            | `data-seed-spec.json` exists, is valid JSON; `name`, `command`, and `targetEnvironments` are declared |
| DS002 | command-path-exists   | The script or binary path in `command` must resolve to an existing file in the repository |
| DS003 | idempotency-declared  | `idempotencyContract` (preferred) or `idempotent: true` + `idempotencyDescription` must be declared |
| DS004 | no-production-target  | `targetEnvironments` must not include `production`/`prod` without `productionOverride: true` |
| DS005 | db-refs-declared      | Every entry in `dbRefs` must declare `envKey` or `secretName` — unmapped refs fail at connection time |
| DS006 | no-todos              | `data-seed-spec.json` contains no `TODO`, `FIXME`, `HACK`, `XXX`, or `PLACEHOLDER` markers |
| DS007 | contract-data-seed    | `owner` is declared; `idempotencyContract` or `idempotent: true` is declared |

## Required Output Files

- `data-seed-spec.json` — author-maintained seed job declaration
- `data-seed-artifact.json` — generated by the compiler on full gate pass

## data-seed-spec.json Structure

```json
{
  "name": "seed-roles",
  "command": "scripts/seed-roles.mjs",
  "owner": "backend-team",
  "targetEnvironments": ["development", "staging"],
  "idempotencyContract": "upsert",
  "dbRefs": [
    {
      "name": "primary",
      "envKey": "DATABASE_URL"
    }
  ]
}
```

## Field Reference

| Field                    | Required    | Notes |
|--------------------------|-------------|-------|
| `name`                   | yes (DS001) | Seed job identifier |
| `command`                | yes (DS001) | Path to seed script — must exist in repo |
| `targetEnvironments`     | yes (DS001) | Non-empty array; `production`/`prod` requires `productionOverride: true` |
| `owner`                  | yes (DS007) | Team or email for accountability |
| `idempotencyContract`    | conditional | Named strategy — preferred over legacy `idempotent: true` |
| `idempotent`             | conditional | Legacy boolean — requires `idempotencyDescription` when true |
| `idempotencyDescription` | conditional | Required when `idempotent: true` is used |
| `productionOverride`     | no          | `true` to allow production targets — must be explicitly justified |
| `dbRefs`                 | no          | Array of `{ name, envKey?, secretName? }` — each must have at least one |

## Idempotency Strategy Reference

| Strategy           | Meaning |
|--------------------|---------|
| `upsert`           | Insert or update — safe on re-run, no duplicates |
| `skip-existing`    | Insert only when row doesn't exist — check by natural key |
| `truncate-insert`  | Truncate table first, then insert all — idempotent but destructive |
| `merge`            | SQL MERGE / ON CONFLICT — database-native upsert |
| `idempotent-insert`| INSERT IGNORE or equivalent — silently skips conflicts |

## Error Codes

| Code  | Trigger | Fix |
|-------|---------|-----|
| DS001 | `data-seed-spec.json` missing | Create the file with `name`, `command`, `targetEnvironments` |
| DS002 | `command: "scripts/missing.mjs"` — file doesn't exist | Create the seed script or fix the path |
| DS003 | No `idempotencyContract` and no `idempotent` | Add `idempotencyContract: "upsert"` |
| DS003 | `idempotencyContract: "delete-insert"` | Not recognised — use `upsert`, `skip-existing`, `truncate-insert`, `merge`, or `idempotent-insert` |
| DS003 | `idempotent: true` with no `idempotencyDescription` | Add `idempotencyDescription: "Uses ON CONFLICT DO UPDATE..."` |
| DS003 | `idempotent: false` | Hard rejection — seed jobs must always be idempotent |
| DS004 | `targetEnvironments: ["staging", "production"]` | Remove `production` or add `productionOverride: true` |
| DS005 | `dbRefs: [{ name: "primary" }]` without `envKey` or `secretName` | Add `envKey: "DATABASE_URL"` |
| DS007 | No `owner` | Add `owner: "backend-team"` |
