# DB Migration Runner — Implementation Guide

## Purpose

Define a database migration runner that is safe to execute in a shared, transactional environment.
A migration without an ordering policy runs in arbitrary file order — a post-deploy cleanup script
may run before the new code it was designed to clean up after, corrupting live data. A migration
command that isn't an allowlisted tool may be an arbitrary shell script executing in a
highly-privileged database context. A hardcoded credential in the spec is committed to source
control and appears in CI logs. A migration without a rollback command leaves a failed schema
change permanently applied to the database with no automated recovery path. This compiler enforces
all of these constraints before emitting an artifact.

## Invariants

| Code  | Gate                    | What It Enforces |
|-------|-------------------------|------------------|
| MR001 | spec-valid              | `db-migration-runner-spec.json` exists, is valid JSON; `command`, `migrationDir`, and `orderingPolicy` are declared |
| MR002 | migration-dir-exists    | The directory declared in `migrationDir` must exist in the repository |
| MR003 | command-allowlisted     | `command` must include a recognised migration tool — arbitrary shell commands are rejected |
| MR004 | credentials-via-env     | No literal credential values in the spec — connection strings and passwords must reference env vars |
| MR005 | ordering-explicit       | `orderingPolicy` must be `pre-deploy`, `deploy`, or `post-deploy` |
| MR006 | no-todos                | `db-migration-runner-spec.json` contains no `TODO`, `FIXME`, `HACK`, `XXX`, or `PLACEHOLDER` markers |
| MR007 | contract-migration-runner| `rollbackCommand` and `timeoutSeconds` must be declared |

## Required Output Files

- `db-migration-runner-spec.json` — author-maintained migration runner declaration
- `migration-runner-artifact.json` — generated by the compiler on full gate pass

## db-migration-runner-spec.json Structure

```json
{
  "command": "prisma migrate deploy",
  "migrationDir": "prisma/migrations",
  "orderingPolicy": "pre-deploy",
  "rollbackCommand": "prisma migrate reset --force",
  "timeoutSeconds": 300,
  "databaseUrl": "$DATABASE_URL"
}
```

## Field Reference

| Field              | Required    | Notes |
|--------------------|-------------|-------|
| `command`          | yes (MR001) | Must include an allowlisted migration tool |
| `migrationDir`     | yes (MR001) | Must exist in the repository |
| `orderingPolicy`   | yes (MR001) | When to run relative to deployment |
| `rollbackCommand`  | yes (MR007) | Command to undo this migration on failure |
| `timeoutSeconds`   | yes (MR007) | Positive integer — prevents stuck migrations blocking the pipeline |
| `databaseUrl`      | conditional | Must be an env var reference (`$MY_VAR`) — never a literal URL with credentials |

## Allowed Migration Commands

| Tool | Example Command |
|------|-----------------|
| Prisma | `prisma migrate deploy` or `npx prisma migrate deploy` |
| Drizzle | `drizzle-kit migrate` |
| Knex | `knex migrate:latest` |
| db-migrate | `db-migrate up` |
| Flyway | `flyway migrate` |
| Liquibase | `liquibase update` |
| Django | `python manage.py migrate` |
| Custom | `migrate` (bare command) |

## Ordering Policy Reference

| Policy        | When It Runs | Best For |
|---------------|--------------|----------|
| `pre-deploy`  | Before new pods start | **Safest** — additive migrations (new columns, tables, indexes). Old code still runs while migration executes, so it must be backward compatible |
| `deploy`      | In parallel with rollout | Non-breaking, in-place changes where old and new code both work with the new schema |
| `post-deploy` | After all new pods are healthy | Cleanup (drop deprecated columns, remove old indexes). New code must already be running |

## Error Codes

| Code  | Trigger | Fix |
|-------|---------|-----|
| MR001 | `db-migration-runner-spec.json` missing | Create the file with `command`, `migrationDir`, `orderingPolicy` |
| MR001 | Missing `orderingPolicy` | Add `orderingPolicy: "pre-deploy"` (or `deploy` or `post-deploy`) |
| MR002 | `migrationDir: "db/migrations"` — directory doesn't exist | Create the directory or fix the path |
| MR003 | `command: "bash ./migrate.sh"` | Replace with a recognised tool: `flyway migrate`, `prisma migrate deploy`, etc. |
| MR003 | `command: "atlas schema apply"` | Not in the allowlist — open a PR to add it, or use an approved alternative |
| MR004 | `databaseUrl: "postgres://user:pass@host/db"` | Replace with `"$DATABASE_URL"` — inject the value at runtime |
| MR005 | `orderingPolicy: "before-deploy"` | Use `"pre-deploy"` — the exact string matters |
| MR007 | No `rollbackCommand` | Add `rollbackCommand: "prisma migrate reset --force"` (or the equivalent undo command) |
| MR007 | No `timeoutSeconds` | Add `timeoutSeconds: 300` — 5 minutes is a reasonable default for most migrations |
