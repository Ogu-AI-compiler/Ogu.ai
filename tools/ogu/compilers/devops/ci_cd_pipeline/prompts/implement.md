# CI/CD Pipeline — Implementation Guide

## Purpose

Define a CI/CD pipeline that cannot silently deploy broken or insecure code. A pipeline with no
triggers never runs automatically — code accumulates unverified. A pipeline with hardcoded secrets
commits credentials to source control and exposes them in build logs. A pipeline without a test
stage is a deployment script: it ships code without any quality signal. A deploy job without a
branch filter runs on every feature branch push, releasing unreviewed code to production. A cyclic
job dependency deadlocks the pipeline permanently. This compiler enforces all of these constraints
before emitting an artifact.

## Invariants

| Code   | Gate                   | What It Enforces |
|--------|------------------------|------------------|
| CIP001 | spec-valid             | `ci-cd-spec.json` exists, is valid JSON; `platform` is one of the supported providers; `triggers`, `stages`, and `jobs` are non-empty |
| CIP002 | trigger-defined        | At least one valid trigger is declared; unknown trigger names are rejected — the platform silently ignores them |
| CIP003 | jobs-staged            | Every job has a `name`, references a stage from `spec.stages`, declares at least one `steps`/`script`/`run`, and all `needs` references point to existing jobs |
| CIP004 | no-cyclic-needs        | Job dependency graph is acyclic — a cycle causes permanent pipeline deadlock |
| CIP005 | no-secret-literals     | No line matches a secret-named key with a long literal value; safe patterns (`${{ secrets.X }}`, `$MY_VAR`, `vault:kv`) are exempted |
| CIP006 | required-quality-gates | Pipeline includes a build stage (build/compile/package/bundle) AND a test stage (test/spec/lint/check/validate/quality) |
| CIP007 | no-todos               | `ci-cd-spec.json` contains no `TODO`, `FIXME`, `HACK`, `XXX`, or `PLACEHOLDER` markers |
| CIP008 | contract-ci-cd         | Deploy jobs have a branch filter; >3 jobs without timeouts are flagged; >2 jobs need at least one artifact/cache entry |

## Required Output Files

- `ci-cd-spec.json` — author-maintained pipeline declaration
- `ci-cd-artifact.json` — generated by the compiler on full gate pass

## ci-cd-spec.json Structure

```json
{
  "platform": "github",
  "service": "api-gateway",
  "triggers": ["push", "pull_request"],
  "stages": ["lint", "test", "build", "deploy"],
  "jobs": [
    {
      "name": "lint",
      "stage": "lint",
      "steps": ["npm run lint"],
      "timeout": "10m",
      "cache": { "key": "node-modules-${{ hashFiles('package-lock.json') }}", "paths": ["node_modules"] }
    },
    {
      "name": "test",
      "stage": "test",
      "needs": ["lint"],
      "steps": ["npm test -- --coverage"],
      "timeout": "20m",
      "artifacts": { "paths": ["coverage/"] }
    },
    {
      "name": "build",
      "stage": "build",
      "needs": ["test"],
      "steps": ["npm run build", "docker build -t $IMAGE ."],
      "timeout": "15m"
    },
    {
      "name": "deploy-production",
      "stage": "deploy",
      "needs": ["build"],
      "branches": ["main"],
      "steps": ["helm upgrade --install api-gateway ./charts/api-gateway"],
      "timeout": "10m",
      "env": {
        "REGISTRY_PASSWORD": "${{ secrets.REGISTRY_PASSWORD }}"
      }
    }
  ]
}
```

## Field Reference

| Field              | Required    | Notes |
|--------------------|-------------|-------|
| `platform`         | yes (CIP001)| See platform reference table below |
| `triggers`         | yes (CIP001)| Non-empty; each must be a valid trigger name |
| `stages`           | yes (CIP001)| Non-empty; must include build and test patterns |
| `jobs`             | yes (CIP001)| Non-empty; each job must reference a declared stage |
| `jobs[].name`      | yes (CIP003)| Unique job identifier; used in `needs` references |
| `jobs[].stage`     | conditional | Must match a value in `spec.stages` |
| `jobs[].steps`/`script`/`run` | yes (CIP003) | At least one must be declared |
| `jobs[].needs`     | no          | Array of job names that must complete first; all must exist |
| `jobs[].branches`/`only`/`if`/`when` | required for deploy jobs (CIP008) | Branch filter to prevent uncontrolled deploys |
| `jobs[].timeout`   | recommended | Format: `"30m"` or `timeout_minutes: 30` |
| `jobs[].artifacts`/`cache`/`outputs` | recommended | At least one needed when >2 jobs |

## Platform Reference

| Platform     | Trigger Format | Secret Format | Branch Filter |
|--------------|----------------|---------------|---------------|
| `github`     | `push`, `pull_request`, `workflow_dispatch` | `${{ secrets.MY_SECRET }}` | `if: github.ref == 'refs/heads/main'` |
| `gitlab`     | `push`, `merge_request`, `schedule` | `$MY_SECRET`, `$CI_*` | `only: [main]` |
| `jenkins`    | `push`, `pull_request`, `manual` | `${MY_SECRET}` | `when { branch 'main' }` |
| `circleci`   | `push`, `tag` | `$MY_SECRET` | `filters: branches: only: [main]` |
| `buildkite`  | `push`, `pull_request`, `schedule` | `$$MY_SECRET` | `branches: "main"` |

## Trigger Reference

| Trigger             | When It Fires |
|---------------------|---------------|
| `push`              | Every commit pushed to any branch |
| `pull_request`      | PR opened, updated, or synced |
| `merge_request`     | GitLab MR opened or updated |
| `schedule`          | Cron-based schedule (nightly builds) |
| `manual`            | Triggered explicitly by a user |
| `tag`               | When a git tag is pushed |
| `workflow_dispatch` | GitHub manual trigger with inputs |
| `release`           | When a GitHub release is published |

## Error Codes

| Code   | Trigger | Fix |
|--------|---------|-----|
| CIP001 | `ci-cd-spec.json` missing | Create the file with `platform`, `triggers`, `stages`, `jobs` |
| CIP001 | `platform: "azure-devops"` | Not supported — use `github`, `gitlab`, `jenkins`, `circleci`, or `buildkite` |
| CIP001 | `jobs: []` | Add at least one job |
| CIP002 | `triggers: []` | Add at least one trigger: `["push", "pull_request"]` |
| CIP002 | `triggers: ["commit"]` | `commit` is not a valid trigger — use `push` |
| CIP003 | Job with `stage: "integration"` but stages is `["lint","test","build"]` | Add `"integration"` to `stages` or fix the job's stage reference |
| CIP003 | Job with no `steps`, `script`, or `run` | Add executable steps to the job |
| CIP003 | `needs: ["nonexistent-job"]` | Fix the job name or add the missing job |
| CIP004 | `job-a needs job-b, job-b needs job-a` | Remove one of the dependencies |
| CIP005 | `env: { DB_PASSWORD: "mypassword123456" }` | Replace with `${{ secrets.DB_PASSWORD }}` |
| CIP006 | No build stage | Add a stage named `build`, `compile`, `package`, or `bundle` |
| CIP006 | No test stage | Add a stage named `test`, `lint`, `spec`, `check`, `validate`, or `quality` |
| CIP008 | Deploy job with no branch filter | Add `branches: [main]` or `if: ${{ github.ref == 'refs/heads/main' }}` |
| CIP008 | 5 jobs, none with timeouts | Add `timeout: "30m"` to each job |
| CIP008 | 3 jobs, no artifacts or cache | Add `cache: { key, paths }` to the install job |
