# Background Worker Runtime — Implementation Guide

## Purpose

Define a background worker that processes messages safely under production conditions.
A worker without a dead-letter queue silently discards messages that fail after all retries —
the data is gone with no trace. A worker without concurrency bounds will consume messages
as fast as the broker delivers them, exhausting CPU and memory until it OOM-crashes. A
worker without a graceful shutdown period interrupts messages mid-processing on every
deploy. This compiler enforces all of these constraints before emitting an artifact.

## Invariants

| Code  | Gate                    | What It Enforces |
|-------|-------------------------|------------------|
| BW001 | spec-valid              | `bg-worker-spec.json` exists, is valid JSON; `name`, `image`, and a non-empty `queues` array are required |
| BW002 | image-refs-valid        | Container image must be pinned to a version tag or SHA digest — mutable tags cause non-deterministic restarts |
| BW003 | queue-bindings-valid    | Every queue entry must declare `name` (queue address) and `connection` (env var name pointing to broker URL) |
| BW004 | grace-period-set        | A graceful shutdown period must be declared to prevent in-flight message interruption during restarts |
| BW005 | worker-not-exposed      | Workers must not declare HTTP ports — an exposed port belongs in a service compiler, not a worker compiler |
| BW006 | autoscaling-bounds-valid | When HPA/KEDA is declared: `minReplicas` ≥ 1, `maxReplicas` > `minReplicas` (skipped when no autoscaling) |
| BW007 | no-todos                | `bg-worker-spec.json` contains no `TODO`, `FIXME`, `HACK`, `XXX`, or `PLACEHOLDER` markers |
| BW008 | contract-worker-runtime | `deadLetterQueue`, `owner`, `maxRetries` (non-negative integer), and `concurrency` (positive integer) are all required |

## Required Output Files

- `bg-worker-spec.json` — worker declaration (queues, concurrency, retry policy, DLQ)
- `worker-runtime-artifact.json` — generated by the compiler on full gate pass

## bg-worker-spec.json Structure

```json
{
  "name": "order-processor",
  "image": "registry.example.com/order-processor:2.1.4",
  "owner": "orders-team",
  "queues": [
    { "name": "orders-queue",  "connection": "REDIS_URL" },
    { "name": "priority-queue", "connection": "REDIS_URL" }
  ],
  "concurrency": 10,
  "maxRetries": 3,
  "backoff": "exponential",
  "deadLetterQueue": "orders-dlq",
  "timeoutMs": 30000,
  "terminationGracePeriodSeconds": 60,
  "resources": {
    "requests": { "cpu": "100m", "memory": "128Mi" },
    "limits":   { "memory": "512Mi" }
  },
  "autoscaling": {
    "type": "keda",
    "minReplicas": 1,
    "maxReplicas": 20,
    "trigger": { "type": "redis", "queueLength": 100 }
  }
}
```

| Field                          | Required     | Notes |
|--------------------------------|--------------|-------|
| `name`                         | yes          | Used in IR ID: `WORKER_RUNTIME:{name}` |
| `image`                        | yes          | Must be pinned — no `:latest` |
| `owner`                        | yes (BW008)  | Team responsible for this worker |
| `queues`                       | yes          | Non-empty; each entry needs `name` + `connection` |
| `concurrency`                  | yes (BW008)  | Max parallel message slots |
| `maxRetries`                   | yes (BW008)  | Non-negative integer; 0 = no retries, goes straight to DLQ |
| `deadLetterQueue`              | yes (BW008)  | Queue name for exhausted messages |
| `backoff`                      | no           | `linear`, `exponential`, or `fixed` |
| `timeoutMs`                    | recommended  | Processing timeout per message |
| `terminationGracePeriodSeconds` | yes (BW004) | Graceful shutdown window |

## Error Codes

| Code  | Trigger | Fix |
|-------|---------|-----|
| BW001 | `bg-worker-spec.json` missing | Create the file with `name`, `image`, and `queues` |
| BW001 | `queues` is empty | Add at least one queue: `[{ "name": "orders-queue", "connection": "REDIS_URL" }]` |
| BW002 | `image: worker:latest` | Pin to `worker:2.1.4` or a SHA digest |
| BW003 | Queue missing `connection` | Add `connection: "REDIS_URL"` (env var name, not the literal URL) |
| BW003 | Queue missing `name` | Add `name: "orders-queue"` |
| BW004 | No `terminationGracePeriodSeconds` or `shutdownTimeoutMs` | Add `terminationGracePeriodSeconds: 60` |
| BW005 | `ports: [3000]` declared | Remove `ports` — workers must not expose HTTP; use a separate service compiler |
| BW006 | `minReplicas: 0` | Minimum is 1 — zero causes cold-start latency under burst load |
| BW006 | `maxReplicas` ≤ `minReplicas` | `maxReplicas` must be greater than `minReplicas` |
| BW008 | No `deadLetterQueue` | Add `deadLetterQueue: "orders-dlq"` |
| BW008 | No `owner` | Add `owner: "orders-team"` |
| BW008 | No `maxRetries` | Add `maxRetries: 3` |
| BW008 | `maxRetries: -1` | Must be a non-negative integer |
| BW008 | No `concurrency` | Add `concurrency: 10`, or `skipConcurrencyCheck: true` if broker enforces this |
