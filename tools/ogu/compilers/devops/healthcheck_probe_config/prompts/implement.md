# Healthcheck Probe Config Compiler — Implementation Guide

## Purpose

Define Kubernetes probe configurations that correctly signal container health. A missing
readiness probe means traffic is sent to containers still running migrations or initialising
their connection pools. A liveness.successThreshold > 1 is silently rejected by the Kubernetes
API server. A liveness probe with initialDelaySeconds shorter than the startup window kills
the container before it finishes starting. This compiler validates all of these relationships
before emitting an artifact.

## Invariants

| Code  | Gate                  | What It Enforces |
|-------|-----------------------|------------------|
| PC001 | spec-valid            | `probe-config-spec.json` exists, is valid JSON; `containerPorts` (non-empty) and `probes` are required |
| PC002 | both-probes-defined   | Both `probes.liveness` and `probes.readiness` must be defined — neither can be omitted |
| PC003 | probe-schema-valid    | Each probe has exactly one handler (`httpGet`/`tcpSocket`/`exec`/`grpc`) with all required fields. Kubelet rejects probes with missing handler fields |
| PC004 | thresholds-valid      | All timing fields are positive integers; `liveness.successThreshold` must be exactly `1` — the API server rejects any other value |
| PC005 | ports-exist           | Ports referenced in probe handlers must be declared in `spec.containerPorts` |
| PC006 | no-todos              | `probe-config-spec.json` contains no `TODO`, `FIXME`, `HACK`, `XXX`, or `PLACEHOLDER` markers |
| PC007 | contract-probe-config | `liveness.initialDelaySeconds` ≥ startup max time (`periodSeconds × failureThreshold`); `readiness.failureThreshold` ≤ `liveness.failureThreshold` |

## Required Output Files

- `probe-config-spec.json` — probe declarations (containerPorts, liveness, readiness, startup)
- `probe-config-artifact.json` — generated by the compiler on full gate pass

## probe-config-spec.json Structure

```json
{
  "service": "api",
  "containerPorts": [
    { "name": "http", "port": 3000 }
  ],
  "probes": {
    "startup": {
      "httpGet": { "path": "/health", "port": 3000 },
      "initialDelaySeconds": 0,
      "periodSeconds": 5,
      "failureThreshold": 12,
      "successThreshold": 1
    },
    "liveness": {
      "httpGet": { "path": "/health", "port": 3000 },
      "initialDelaySeconds": 60,
      "periodSeconds": 30,
      "timeoutSeconds": 5,
      "failureThreshold": 3,
      "successThreshold": 1
    },
    "readiness": {
      "httpGet": { "path": "/ready", "port": 3000 },
      "initialDelaySeconds": 5,
      "periodSeconds": 10,
      "timeoutSeconds": 3,
      "failureThreshold": 3,
      "successThreshold": 1
    }
  }
}
```

## Probe Handlers Reference

| Handler     | Required Fields | Use Case |
|-------------|-----------------|----------|
| `httpGet`   | `path`, `port`  | HTTP services with health endpoint |
| `tcpSocket` | `port`          | TCP services (databases, message brokers) |
| `exec`      | `command` (non-empty array) | Custom scripts or CLI health checks |
| `grpc`      | `port`          | gRPC services with health.v1 protocol |

## Timing Relationships (PC007)

The startup window = `startup.periodSeconds × startup.failureThreshold` = 5 × 12 = **60s**.
`liveness.initialDelaySeconds` must be ≥ 60s (otherwise liveness kills the container before startup completes).
`readiness.failureThreshold` (3) must be ≤ `liveness.failureThreshold` (3) so traffic stops before the restart.

## Error Codes

| Code  | Trigger | Fix |
|-------|---------|-----|
| PC001 | `probe-config-spec.json` missing | Create the file with `containerPorts` and `probes` |
| PC001 | `containerPorts` is empty | Add at least one port: `[{ "name": "http", "port": 3000 }]` |
| PC002 | No `probes.liveness` | Add a liveness probe with `httpGet`, `tcpSocket`, `exec`, or `grpc` |
| PC002 | No `probes.readiness` | Add a readiness probe — it controls when the pod receives traffic |
| PC003 | Probe has no handler | Add one of: `httpGet`, `tcpSocket`, `exec`, or `grpc` |
| PC003 | `httpGet` missing `path` or `port` | Add `httpGet: { path: "/health", port: 3000 }` |
| PC003 | `exec.command` is empty | Provide a non-empty command array: `["sh", "-c", "wget -qO- http://localhost:3000/health"]` |
| PC004 | `failureThreshold: 0` | Must be a positive integer (minimum 1) |
| PC004 | `liveness.successThreshold: 2` | Must be exactly `1` — Kubernetes API server rejects other values |
| PC005 | Probe port `8080` not in `containerPorts` | Add `{ "name": "metrics", "port": 8080 }` to `containerPorts` |
| PC007 | `liveness.initialDelaySeconds: 10` but startup max is 60s | Increase `liveness.initialDelaySeconds` to at least 60 |
| PC007 | `readiness.failureThreshold: 5` > `liveness.failureThreshold: 3` | Decrease readiness failureThreshold to ≤ 3 |
