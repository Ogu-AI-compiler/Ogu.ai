Breakdown1. db-instance-specName: Database Provisioning CompilerFrequency: Per-Project / Per-Scale EventInput: Estimated Request per Second (RPS), Data Growth rate, Concurrent Connections.Output: instance_manifest.json (CPU, RAM, IOPS, Storage Type).Correctness Gates: _ Storage must include an auto-scaling policy with a maximum threshold.IOPS must meet the minimum required for the specified instance class.Dependencies: None.Downstream Consumers: db-connection-policy, Infrastructure Provisioner.Spec file: {"engine": "postgres", "version": "16", "instance": "db.m6g.xlarge", "storage": {"initial": 100, "max": 1000}}Error codes: DBA101 (Under-provisioned RAM), DBA102 (IOPS Bottleneck), DBA103 (Engine Version Mismatch).Key invariant: Storage allocation must never exceed the provider's regional limits.Safe default: Smallest burstable instance with 20GB storage.2. db-access-policyName: Database RBAC CompilerFrequency: Per-FeatureInput: Service IDs, db-migration (target tables), auth-middleware scopes.Output: rbac_policy.json (GRANT/REVOKE statements, Role definitions).Correctness Gates: _ No application service account can have SUPERUSER or OWNER privileges.Every table in the database must have a designated owner role.Dependencies: db-migration.Downstream Consumers: db-audit-policy, Database Migrator.Spec file: {"role": "app_writer", "grants": [{"schema": "public", "privilege": "INSERT", "on": ["orders"]}]}Error codes: DBA201 (Excessive Privileges), DBA202 (Missing Table Grant), DBA203 (Public Schema Vulnerability).Key invariant: Application roles must not have permission to execute DROP TABLE or TRUNCATE.Safe default: Read-only access to a dedicated "public" schema.3. db-connection-policyName: Pooling & Proxy CompilerFrequency: DailyInput: Total App Nodes, api-route definitions, Max Connections from db-instance-spec.Output: pgbouncer_config.json / pool_manifest.json.Correctness Gates: _ Total Pool Size (across all instances) must be $\leq 90\%$ of max_connections.Transaction timeout must be shorter than the api-route gateway timeout.Dependencies: db-instance-spec, api-route.Downstream Consumers: PgBouncer, App Environment Config.Spec file: {"pool_mode": "transaction", "max_client_conn": 1000, "default_pool_size": 20}Error codes: DBA301 (Connection Exhaustion), DBA302 (Idle Timeout Mismatch), DBA303 (Zombie Connection Leak).Key invariant: The sum of all pool sizes must never trigger the database's hard connection limit.Safe default: Session pooling with a limit of 10 connections per node.4. db-performance-budgetName: Query Performance CompilerFrequency: DailyInput: P99 Latency targets, Slow Query Logs, API SLOs.Output: perf_budget.json (Statement timeout limits, Workload classes).Correctness Gates: _ No transaction can exceed the defined max_transaction_duration (preventing lock pile-ups).Read queries on replicas must have a lower timeout than primary writes.Dependencies: api-route.Downstream Consumers: db-index-advisory, Monitoring System.Spec file: {"workloads": {"oltp": {"statement_timeout": "5s"}, "reports": {"statement_timeout": "30s"}}}Error codes: DBA401 (Budget Overrun), DBA402 (Long Running Transaction), DBA403 (Deadlock Threshold Exceeded).Key invariant: Latency budgets must be tighter than the user-facing API response requirements.Safe default: Global statement timeout of 30 seconds.5. db-index-advisoryName: Index Strategy CompilerFrequency: Daily (or per-migration)Input: db-migration schema, Query execution plans (EXPLAIN), Slow query telemetry.Output: index_plan.json (CREATE/DROP INDEX recommendations).Correctness Gates: _ Every index must have a recorded "usage count" > 0 over 7 days (prevents unused indexes).No table can have more than 10 indexes without a manual waiver.Dependencies: db-migration, db-performance-budget.Downstream Consumers: CI/CD Migration Runner.Spec file: {"table": "users", "add": [{"columns": ["email"], "unique": true}], "remove": ["idx_unused_temp"]}Error codes: DBA501 (Redundant Index), DBA502 (Missing High-Cardinality Index), DBA503 (Write-Heavy Table Over-Indexed).Key invariant: An index must not be created if it increases write latency beyond the db-performance-budget.Safe default: Primary key and Foreign key indexes only.6. db-backup-policyName: Backup & Retention CompilerFrequency: Per-ProjectInput: RPO (Recovery Point Objective), RTO (Recovery Time Objective), Legal retention years.Output: backup_schedule.json.Correctness Gates: _ Backup schedule must include a "Point-in-Time Recovery" (PITR) window.Retention must be $\geq$ the minimum legal requirement for the data classification.Dependencies: db-instance-spec.Downstream Consumers: db-restore-verification.Spec file: {"snapshot_frequency": "24h", "pitr_window": "7d", "archive_retention": "7y"}Error codes: DBA601 (RPO Not Met), DBA602 (Retention Gap), DBA603 (Incomplete WAL Archiving).Key invariant: Backup storage must be geographically redundant relative to the primary instance.Safe default: Daily snapshots with 7-day retention.7. db-restore-verificationName: Restore Attestation CompilerFrequency: Daily (Automated Drill)Input: db-backup-policy, Latest Backup Artifact.Output: restore_attestation.json (Success/Fail, Time taken, Data integrity check).Correctness Gates: _ Restore time must be $\leq$ RTO defined in db-backup-policy.Row counts for critical tables must match source at backup timestamp.Dependencies: db-backup-policy.Downstream Consumers: Compliance Dashboard.Spec file: {"last_drill": "2024-05-20T04:00Z", "rto_status": "PASS", "integrity_check": "MATCH"}Error codes: DBA701 (Restore Failed), DBA702 (RTO Breach), DBA703 (Checksum Mismatch).Key invariant: A backup is considered non-existent until its most recent restore drill passes.Safe default: None (Manual alert on failure).8. db-data-masking-specName: Anonymization CompilerFrequency: Per-Project / Per-Schema ChangeInput: ts-schema (with PII annotations), Target environment (Staging/Dev).Output: masking_rules.sql / anonymizer_config.json.Correctness Gates: _ Every column marked "PII" in ts-schema must have a corresponding masking rule.Masked data must maintain referential integrity (same ID maps to same hash).Dependencies: ts-schema, db-migration.Downstream Consumers: Data Pipeline (Prod-to-Staging).Spec file: {"rules": [{"column": "email", "method": "hash"}, {"column": "phone", "method": "random"}]}Error codes: DBA801 (PII Leak), DBA802 (Referential Integrity Broken), DBA803 (Unmasked Sensitive Column).Key invariant: Staging environments must never contain plaintext user-identifiable data.Safe default: Nullify all columns in staging unless explicitly whitelisted.Recommended Build OrderTier
